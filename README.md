# GE6 Vote Tracker

A Thai-language, mobile-first results site for the **BNK48 & CGM48 General Election 6** token vote
on the Token X chain. Voting closed on **12 Nov 2026 at 21:00 (Bangkok)**. The site started as a
real-time tracker of the hashed on-chain votes; now that the official per-vote result export is
out, every number comes from that file and every page is static (no auto-refresh, no polling).

## What the home page shows (`/`)

- Final totals: 1,672,642.55 GE6, 5,649 wallets, 43,581 votes, 58 members; the top 3; BNK48 vs CGM48.
- **Member ranking**: all 58 members with tokens, share, wallets, votes, rank change since GE5,
  and each member's #1 wallet. Filter by group, sort by tokens / wallets / votes / average / climb.
- **#1 wallet for each member**: the wallet that gave each member the most, how much, and what share
  of her total that is (plus wallets that are #1 for several members).
- **Highlights**: biggest wallet, largest single vote, biggest climber from GE5, broadest fan base,
  most whale-dependent, most single-oshi support, biggest final-day surge, busiest wallet, a
  wallet that voted for all 58, first and last vote.
- **Top 10–100 wallets** with who each voted for.
- **When people voted**: per day (tokens / votes / new wallets), cumulative, the final 24 hours by
  hour, and by hour of day. Vote times come from the first 10 digits of each row's `Key` (unix time).
- **How many members a wallet voted for**, and the member pairs that share the most wallets.
- **GE5 → GE6**: returning wallets, biggest rank moves, and where the fans of GE5 members who
  aren't in GE6 went.
- Wallet size distribution, a wallet lookup (GE6 rank and member breakdown), and the token
  journey frozen at the close (created → distributed → voted; fans used 99.96% of what they got).

## Member pages (`/member/[slug]`, e.g. `/member/pancake-bnk48`)

One prerendered page per member: rank and GE3–GE5 history, wallets, votes, average/median, her
#1 wallet, her top 50 wallets (share of her total, whether they voted only for her), tokens per
day, share from single-member wallets, GE5 fan retention, which other members her wallets also
voted for, and her wallet-size distribution.

## Data

| File | Built by | Used by |
| --- | --- | --- |
| `src/data/ge6-results.json` | `scripts/build-ge6-results.mjs` | home page |
| `src/data/ge6-members.json` | `scripts/build-ge6-results.mjs` | `/member/[slug]` |
| `src/data/ge6-{top,summary,wallets}.json` | `scripts/build-past-ge-data.mjs ge6` | `/compare`, `/ge3`–`/ge5`, `/wallet` |
| `src/data/ge6-tokens.json` | one-off chain snapshot (below) | token journey on `/` |

Regenerate everything GE6 from the official export (`ge6_result.csv` in the repo root, git-ignored
because it contains app account IDs, vote keys and hashes):

```bash
npm run data:ge6
```

Only addresses, member names, amounts, and times aggregated to days/hours are kept.

`ge6-tokens.json` is the token supply split read on-chain at block 50,696,227 (right after the last
vote) plus the organizer → fan transfer totals from the old live tracker's final sync. At that
block the vote contract held 1,672,643.55 GE6, 1 GE6 more than the official export (the
contract was emptied a few hours later). The live tracker code that produced it is in git history
before this change.

The only live chain read left is `/api/balance/[address]` (a wallet's current GE6 / BNK balance),
fetched when someone opens a wallet, never polled.

## Past elections → GE6 (`/ge3`, `/ge4`, `/ge5`, `/compare`)

Each page lists the 300 wallets that voted the most in that election (GE3, GE4 or GE5). Each row
shows the wallet's past total next to its GE6 total, plus the member it voted for most back then;
expanding a row shows its top 3 back then and who it voted for in GE6. Tap the column headers to
sort, filter by "voted in GE6", or filter by member. A switch at the top moves between GE3, GE4
and GE5.

`/compare` puts GE3–GE6 side by side (newest first): total tokens, wallets, votes, average/median
per wallet, concentration (Top 10 share, wallets making up half the tokens), the #1 member; one
wallet table combining every election's top 300 with GE6 / GE5 / GE4 / GE3 amounts in columns
(sortable, filterable, tap a row for each election's rank and top member); how many wallets
came back in the next election, new wallets per election, wallets that voted in every one, and
each member's rank in GE3–GE6. Members are matched across elections by exact
nickname; GE4 lists nicknames only, so its "Pim" is kept separate from GE3's two Pims.

- All election data is static, generated by one script from each election's export CSV into
  `src/data/<edition>-top.json` (top 300) and `src/data/<edition>-summary.json` (stats, member
  totals, and every voting wallet with its total, for ranks and overlap counts). Both formats are handled: GE3/GE4's
  raw vote lists (one row per vote, amounts in wei, divided by 10^18) and GE5's wallet × member
  totals (amounts already in tokens). Amounts are summed exactly as 18-decimal integers. Only
  addresses, totals, and member names are kept; wallet codes and vote keys/hashes are dropped,
  and the raw CSVs are git-ignored. Wallets tied at the cutoff are all kept. To regenerate
  (change `TOP_N` in `scripts/build-past-ge-data.mjs` for a different size):

  ```bash
  npm run data:all
  ```

  Or one at a time with a custom path:

  ```bash
  npm run data:ge6 -- path/to/ge6_result.csv
  ```


  ```bash
  npm run data:ge4 -- path/to/ge4_result.csv
  ```

  ```bash
  npm run data:ge5 -- path/to/ge5_voters.csv
  ```

- Every page is prerendered at build time; nothing polls.

## Staying on the Vercel Hobby (free) plan

Hobby includes **1M CDN requests** a month, and every request counts, even from cache. With the
vote over, every page is prerendered static HTML (CSS inlined, one variable font, inline logo), so
a visit costs only the page and its static assets, and there is no polling at all. The two API
routes are fetched only on demand: `/api/history/[address]` (static data, cached at the CDN for a
day) and `/api/balance/[address]` (cached for a minute). Member pages and `/wallet`, `/compare`,
`/ge3`–`/ge5` are linked with `prefetch={false}`, so visiting the home page doesn't download them.

## Run locally

```bash
npm install
```

```bash
npm run dev
```

Open http://localhost:3000. No API keys or database are needed.

## Deploy to Vercel

1. Push this repo to GitHub and import it in Vercel. Framework preset: Next.js, no build settings needed.
2. `vercel.json` pins functions to `sin1` (Singapore), close to Thai users and to the Token X node.

Or use the CLI:

```bash
npx vercel --prod
```

## Limitations

- "Wallets" ≠ people; one fan can use several wallets.
- Members are matched across elections by exact name. GE4 lists nicknames only, so its "Pim" is kept separate.
- "New in GE6" means the exact name wasn't in GE5's export.
